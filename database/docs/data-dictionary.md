# JANNet AI — Data Dictionary (Phase 2)

Authoritative source: `database/migrations/`. This document is a readable
companion, not a second source of truth — if it and the migrations ever
disagree, the migrations win. Regenerate/update this file whenever a
migration changes.

Engine: MySQL 8.0+, InnoDB, `utf8mb4` / `utf8mb4_0900_ai_ci` throughout.

## Decision notes (things this phase changed or resolved vs. the source documents)

1. **Database engine: MySQL, not PostgreSQL.** The SRS/BRD/FRS document's own
   tech-stack section (Appendix A.2) specifies PostgreSQL, FastAPI, and
   React.js. That contradicts the stack locked in Phase 1
   (`ARCHITECTURE.md`, `README.md`): MySQL + Flyway, Spring Boot, Flutter.
   This phase was explicitly scoped as **"Phase 2 — MySQL Database +
   Migrations"**, matching the Phase 1 lock-in, so MySQL was used and the
   SRS's Postgres-specific types (`SERIAL`, `JSONB`) were translated to
   MySQL 8 equivalents (`BIGINT UNSIGNED AUTO_INCREMENT`, `JSON`). This
   contradiction is significant enough (frontend framework and backend
   framework too, not just the database) that it should be explicitly
   confirmed with the team/stakeholders before Phase 3 (Spring Boot
   backend) begins, rather than assumed resolved by this phase's default.
   See `ARCHITECTURE.md` Section 9.
2. **Users.ward_id FK target corrected.** SRS Table 19.1 says
   `ward_id INTEGER FK -> Locations.ward_id`, but `Locations`' primary key
   is `location_id`, not `ward_id` — `Wards` is the only table with that
   key. Treated as a typo in the source document and corrected to
   `wards.ward_id`.
3. **Role list expanded from Phase 1's 5-role placeholder to the SRS's
   7-role set.** `CITIZEN, GOVERNMENT_OFFICER, DEPARTMENT_HEAD, ADMIN,
   SUPER_ADMIN, VERIFICATION_TEAM, MAINTENANCE_TEAM` (SRS Section 11; the
   8th role, "AI Processing Engine", is a system actor with no user row).
   `PROJECT_INTEGRATION.md` Section 3 is updated to match in this phase.
4. **`complaints.status` keeps the 12-value enum locked in Phase 1**
   (including `ESCALATED` and `REOPENED` as status values), even though the
   SRS describes escalation/reopening as annotations on the current status
   rather than replacement states. Added `is_escalated`/`escalated_at` and
   `is_reopened`/`reopened_at` so the SRS's actual behavior is directly
   representable without discarding the locked enum. Phase 6 (Complaint
   Module) should pick one approach when it implements the real transition
   table.
5. **`predictions.priority_score` added.** The SRS's Priority Prediction
   Module (15.8) documents a numeric priority score as an output, but the
   SRS's own Predictions table (19.6) omits a column for it. Added to
   actually store the documented output.
6. **`predictions.complaint_id` is not unique**, despite the SRS's ER
   summary describing Complaints -> Predictions as 1:1, to allow the
   AI Analysis Module's documented retry behavior (15.3) to be logged.
7. **`departments.jurisdiction_id` omitted.** SRS references
   `FK -> Locations.ward_id (nullable, or a jurisdiction grouping table)` —
   an already-hedged, inconsistent target. Omitted under the SRS's own
   single-jurisdiction pilot assumption; add a real jurisdictions table if
   multi-jurisdiction support is ever exercised.
8. **`routing_rules` table added.** Not present in the SRS's Database
   Design section, but fully specified as a form (17.4) and required by
   multiple functional modules (15.7, 15.8, 15.9). Not seeded with data in
   this phase — see item 9.
9. **No seeded `routing_rules` or `settings` rows.** Both require a real
   `users.user_id` for `created_by`/`updated_by` (SRS 15.11: only Super
   Admin may create/modify these, and changes must be logged), but no user
   account exists yet — that's Phase 4's bootstrap concern. Only `wards`
   and `departments` (including a `General Triage` fallback department per
   SRS 15.7) are seeded, since the application's documented fallback
   behavior needs `General Triage` to exist as a real row.
10. **Category list includes a `GENERAL` value** not in Phase 1's original
    6-category list, to support the same fallback rule referenced in item 9.
